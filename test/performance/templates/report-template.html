Request Flow Details

  • Fortio Load Generator generates HTTP requests at a fixed rate (500 QPS) with 16 concurrent connections. Runs as a pod inside the cluster with direct access to the Gateway service.
  • Istio Gateway receives the request via Envoy proxy. The Gateway is managed by Istio using the openshift-default GatewayClass on OpenShift 4.22.18.
  • Coraza WAF WASM Plugin (optional, depending on test configuration) inspects the request. Runs inside the Envoy proxy as a WebAssembly module. Rules are statically embedded (not cache-polled) for consistent performance measurement. The WAF evaluates all configured rules (__RULE_COUNT_LIST__ depending on ruleset) and either allows or blocks the request.
  • Backend Echo Service receives allowed requests and returns a simple HTTP response. This service just echoes back request details - no actual application logic. Used as a consistent endpoint for measuring gateway + WAF overhead.
  • Response travels back through the same path: Backend → WAF (if enabled) → Gateway → Fortio. Total latency (request + response) is measured and reported at various percentiles (p50, p95, p99).

What We're Measuring

  • Baseline (WAF OFF): Pure Istio Gateway + Envoy overhead without any WAF filtering. This is our reference point.
  • WAF Overhead: Additional latency introduced by the Coraza WASM plugin when evaluating security rules. Calculated as: (WAF latency - Baseline latency) / Baseline latency.
  • Rule Count Impact: How the number of rules (__WAF_RULE_COUNT_LIST__) affects latency. More rules = more inspection work = higher latency.
  • Request Shape Impact: How request complexity (simple GET, query parameters, headers) affects WAF overhead. CRS rules iterate over ARGS and HEADERS, so more data = more work.

📈 Tail Latency Ratio (Predictability)?Answers one question: is the WAF making latency erratic? Each bar is p99 divided by p50, so it measures how spread out latency is, independently of how slow it is. A bar of 1.0 would mean the slowest 1% of requests are just as fast as a typical one — no tail at all. Low, even bars mean the WAF adds latency consistently on every request, rather than letting some requests stall.
